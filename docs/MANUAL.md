# 사용 매뉴얼 — 미국 앱스토어 키워드 스캐너

> 이 매뉴얼은 코드를 몰라도 따라 할 수 있게 썼습니다. 설치·설정의 짧은 요약은 [README](../README.md)에 있습니다.

## 1. 이 도구가 하는 일 (한눈에)

**"앱을 만들 때 경쟁이 약한 검색어"를 찾아 주는 도구**입니다. 낚시터에 비유하면, 사람(검색)은 오는데 낚싯대(경쟁 앱)는 적은 자리를 찾아 주는 셈입니다.

```
씨앗 단어(budget)
  → ① 미국 앱스토어 자동완성에서 관련 검색어 모으기 (budget app, budget planner …)
  → ② 검색어마다 상위 10개 앱을 조회해 경쟁 정도를 점수로 매기기
  → ③ 경쟁이 약한 순서로 엑셀(keywords_result.xlsx)에 정리
```

씨앗 1개당 보통 검색어 200~260개가 모입니다.

## 2. 처음 한 번만: 준비

1. **터미널**을 엽니다 (Spotlight에서 `터미널` 검색).
2. Python 버전을 확인합니다.
   ```
   python3 --version
   ```
   `Python 3.11` 이상이면 됩니다. 더 설치할 것은 없습니다.
3. 도구가 있는 폴더로 이동합니다. 폴더 이름에 띄어쓰기가 있으므로 따옴표로 감쌉니다.
   ```
   cd "/Volumes/jayden-ssd/projects/Keyword Scanner"
   ```

## 3. 기본 사용법 (3단계)

### ① 씨앗 단어 적기

`seeds.txt`를 텍스트 편집기로 열어, 조사하고 싶은 단어를 **한 줄에 하나씩** 적습니다.

```
# 한 줄에 씨앗 단어 1개 (# 으로 시작하는 줄은 무시)
budget
habit tracker
```

- 영어로 적습니다 (미국 앱스토어 기준).
- 대소문자만 다른 중복(`Budget`, `budget`)은 하나로 합칩니다.

### ② 실행

```
python3 scan.py
```

화면에 진행 상황이 한 줄씩 나옵니다.

```
씨앗 'budget' 수집 완료 — 누적 키워드 207개
키워드 207개 분석 시작 (최대 약 38분, …)
[1/207] budget app — 경쟁 점수 48.6
…
저장 완료: …/keywords_result.xlsx (키워드 207개)
```

### ③ 결과 열기

같은 폴더의 `keywords_result.xlsx`를 Excel·Numbers·Google 시트로 엽니다. 맨 위가 경쟁이 가장 약한 검색어입니다.

## 4. 걸리는 시간

| 인앱결제 확인 (`config.toml`) | 씨앗 1개 (약 200~250 검색어) |
| ----------------------------- | ---------------------------- |
| 켬 (기본, 정확)               | 약 15~20분 (실측 15분)       |
| 끔 (빠름)                     | 약 5분                       |

- 차단을 피하려고 애플에 요청할 때마다 1초씩 쉬기 때문에 걸리는 시간입니다.
- 씨앗이 3개면 대략 3배 걸립니다.
- 실행하는 동안 **터미널 창을 닫지 마세요.** 닫혀도 아래 5장처럼 이어서 할 수 있습니다.

## 5. 중간에 끊겼을 때

**그냥 같은 명령을 다시 치면 됩니다.**

```
python3 scan.py
```

```
이어서 합니다: 키워드 207개 중 31개는 이미 완료 (처음부터 하려면 --fresh)
```

| 상황                                             | 동작                                                                              |
| ------------------------------------------------ | --------------------------------------------------------------------------------- |
| 터미널이 닫힘, Ctrl+C, 컴퓨터 재시작             | 다시 실행하면 끊긴 검색어부터 이어서 함                                           |
| Ctrl+C로 멈춤                                    | 그때까지 결과로 엑셀도 일단 저장해 줌                                             |
| 처음부터 새로 하고 싶음                          | `python3 scan.py --fresh`                                                         |
| 씨앗 단어나 기준값(가중치·대기업 목록 등)을 바꿈 | "설정·씨앗 … 바뀌어 처음부터 합니다"라고 알리고 새로 시작 (옛 기준과 섞이지 않게) |
| 요청 간격(`delay_seconds`)만 바꿈                | 그대로 이어서 함                                                                  |

- 작업 중에는 `keywords_result.progress.jsonl`(진행 기록) 파일이 생깁니다. **지우지 마세요.** 끝까지 성공하면 자동으로 지워집니다.

## 6. 엑셀 결과 읽는 법

### 가장 먼저 볼 열 3개

| 열                  | 뜻                                                                           | 보는 법                                                                                         |
| ------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **경쟁 점수**       | 0~100. **낮을수록 경쟁이 약함**                                              | 맨 위(낮은 점수)부터 봅니다                                                                     |
| **앱 이름 같음**    | "예"면 일반 검색어가 아니라 특정 앱의 이름 (예: `kabuddy: budget & kakeibo`) | **필터로 "아니오"만 남기세요.** 앱 이름은 그 앱을 찾는 사람만 검색하므로 노릴 키워드가 아닙니다 |
| **제목 포함 앱 수** | 상위 10개 중 제목에 이 검색어가 그대로 들어간 앱 수                          | 0~2개면 이 검색어를 정면으로 노린 앱이 적다는 뜻                                                |

### 엑셀에서 "앱 이름" 숨기기

1. 맨 윗줄(머리글)에 필터 단추가 이미 켜져 있습니다.
2. **"앱 이름 같음"** 열의 ▼ 단추 → "예" 체크 해제 → 확인.
3. 이제 일반 검색어만 경쟁이 약한 순으로 남습니다.

### 나머지 열

| 열                       | 뜻                                                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------------------------------- |
| 순위                     | 경쟁 점수 낮은 순 (같으면 리뷰 중간값이 낮은 순)                                                                |
| 씨앗                     | 이 검색어를 만든 씨앗 단어                                                                                      |
| 조회된 앱 수             | 검색 결과 앱 수 (최대 10)                                                                                       |
| 리뷰 중간값·최대값       | 상위 앱들의 평점 수. 중간값이 수백 이하이면 약한 앱이 많은 것                                                   |
| 리뷰 1,000개 미만 앱 수  | 아직 자리 잡지 못한 앱의 수. 많을수록 기회                                                                      |
| 대기업 여부·앱 수·판매자 | Google·Microsoft·Intuit 같은 대기업 앱이 상위에 있는지                                                          |
| 유료·인앱결제 앱 수      | 유료이거나 인앱결제가 있는 앱 수. 많으면 "돈이 되는 시장"이라는 신호로도 볼 수 있음 (점수에는 기본으로 안 넣음) |
| 인앱 확인 실패 수        | 앱 페이지를 못 읽어 인앱결제를 판단하지 못한 앱 수. 보통 0                                                      |

### 경쟁 점수는 이렇게 계산됩니다

아래 항목을 0~1로 바꾼 뒤 가중치를 매겨 평균을 내고 100을 곱합니다 (`config.toml`의 `[score_weights]`).

| 항목              | 기본 가중치 | 경쟁이 강하다고 보는 경우             |
| ----------------- | ----------- | ------------------------------------- |
| 제목 포함 앱 비율 | 3           | 제목에 검색어를 넣은 앱이 많음        |
| 리뷰 중간값       | 3           | 상위 앱들의 리뷰가 대체로 많음        |
| 대기업 앱 비율    | 2           | 대기업 앱이 많음                      |
| 리뷰 최대값       | 1           | 리뷰가 아주 많은 강자가 하나라도 있음 |
| 자리 잡은 앱 비율 | 1           | 리뷰 1,000개 이상 앱이 많음           |
| 유료·인앱 앱 비율 | 0 (안 씀)   | —                                     |

리뷰 수는 로그 눈금이라, 100→1,000의 차이와 10,000→100,000의 차이를 같게 봅니다.

## 7. 설정 바꾸기 (`config.toml`)

텍스트 편집기로 열어 `=` 오른쪽 값만 바꾸고 저장합니다. 자주 바꾸는 것만 정리했습니다.

| 하고 싶은 것                     | 바꿀 값                     | 예                           |
| -------------------------------- | --------------------------- | ---------------------------- |
| 빨리 훑어보기 (인앱 확인 생략)   | `check_in_app_purchases`    | `false`                      |
| "약한 앱" 기준 바꾸기            | `low_review_threshold`      | `500`                        |
| 대기업 목록에 회사 추가          | `[big_companies]`의 `names` | `"Rocket Money",` 한 줄 추가 |
| 점수에서 어떤 항목을 더 중요하게 | `[score_weights]`           | `big_company = 4`            |
| 유료·인앱 앱도 경쟁으로 치기     | `monetized_apps`            | `1`                          |
| 차단이 걱정될 때 천천히          | `delay_seconds`             | `2.0`                        |

- 값이 잘못되면 실행하자마자 `오류: [criteria] low_review_threshold는 0보다 커야 합니다.`처럼 어디가 틀렸는지 알려 줍니다.
- 기준값을 바꾸면 다음 실행은 처음부터 합니다 (5장 참고).

### 다른 파일로 실행하기

```
python3 scan.py --seeds 내씨앗.txt --output 결과_habit.xlsx
```

결과 파일 이름을 바꾸면 기존 `keywords_result.xlsx`를 덮어쓰지 않습니다. **같은 이름으로 다시 실행하면 이전 결과를 덮어씁니다** — 남겨 두려면 실행 전에 파일 이름을 바꿔 두세요.

## 8. 문제가 생겼을 때

| 화면에 나온 말                                  | 원인                                         | 해결                                                          |
| ----------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------- |
| `command not found: python3`                    | Python이 없음                                | python.org에서 3.11 이상 설치                                 |
| `can't open file '…scan.py'`                    | 다른 폴더에서 실행함                         | 2장의 `cd` 명령으로 폴더 이동 후 실행                         |
| `오류: 씨앗 파일을 찾을 수 없습니다`            | `seeds.txt`를 지웠거나 `--seeds` 이름이 틀림 | 파일 이름·위치 확인                                           |
| `오류: 씨앗 파일에 단어가 없습니다`             | `seeds.txt`가 비었거나 모두 `#` 줄           | 단어를 한 줄 이상 적기                                        |
| `분석된 키워드가 없어 엑셀을 만들지 않았습니다` | 인터넷이 끊겼거나 애플이 잠시 막음           | 인터넷 확인 후 몇 분 뒤 다시 실행. `scan.log`에 원인 기록     |
| `인앱 확인 실패 수`가 갑자기 많아짐             | 애플이 앱 페이지 모양을 바꿈                 | `check_in_app_purchases = false`로 두고 사용, 개발자에게 알림 |

- `scan.log`에는 실패하거나 건너뛴 요청만 기록됩니다. 비어 있으면 문제없이 끝난 것입니다.
- 네트워크 오류는 3번까지 다시 시도하고, 그래도 안 되면 그 검색어만 건너뜁니다.

## 9. 알아둘 한계

- **자동완성 주소는 애플의 비공식 주소**라 예고 없이 바뀔 수 있습니다. 갑자기 검색어가 0개로 모이면 이 경우일 수 있습니다.
- **"앱 이름 같음"은 제목이 글자까지 같은지만 봅니다.** "budget daily"처럼 일반 단어와 같은 이름의 앱이 있으면 "예"로 나오고, 상위 10개 안에 그 앱이 없으면 놓칠 수 있습니다. 표시만 하고 지우지는 않으니 최종 판단은 눈으로 해 주세요.
- **경쟁 점수는 "검색량"을 모릅니다.** 애플은 검색량을 공개하지 않습니다. 자동완성에 나온다는 것은 어느 정도 검색된다는 신호일 뿐입니다. 점수가 낮은 후보를 고른 뒤 App Store에서 직접 검색해 확인하세요.
- 미국(US) 스토어 기준입니다.

## 10. 추천 작업 흐름

1. 아이디어 분야의 씨앗 1~3개를 `seeds.txt`에 적고 실행합니다.
2. 엑셀에서 **"앱 이름 같음" = 아니오** 필터를 겁니다.
3. 경쟁 점수가 낮은 상위 20개 중 **리뷰 중간값이 낮고 대기업이 없는** 검색어를 고릅니다.
4. 고른 검색어를 App Store 앱에서 직접 검색해 상위 앱을 눈으로 확인합니다.
5. 괜찮은 검색어를 새 씨앗으로 넣고 다시 실행해 더 깊이 파고듭니다.

## 11. 돈 검증 스캐너 (`money_check.py`)

키워드 스캐너로 고른 후보 키워드에 **"돈 내는 사용자가 있는 시장인가"**를 확인하는 두 번째 도구입니다.

### 사용법 (3단계)

1. `keywords_result.xlsx`를 엑셀로 열고 **맨 끝 열 머리글에 `pass`**라고 적습니다. 검사할 키워드 줄의 pass 칸에 **아무 글자나**(예: `o`) 적고 저장합니다. 빈칸·공백만 있는 칸·체크하지 않은 체크박스(FALSE)·`#N/A` 같은 오류 칸은 건너뜁니다.
2. 터미널에서 실행합니다.
   ```
   python3 money_check.py
   ```
   키워드마다 검색 1번(1초 간격)이라 키워드 60개면 약 1분 걸립니다.
3. 프로젝트 폴더에 생긴 `money_check.xlsx`를 엽니다.

> ⚠️ 키워드 스캐너(`scan.py`)를 다시 돌리면 `keywords_result.xlsx`를 새로 만들어서 **적어 둔 pass 표시가 사라집니다.** 표시한 파일을 다른 이름으로 저장해 두고 `python3 money_check.py --input 다른이름.xlsx`처럼 실행하면 안전합니다.

### 결과 엑셀

**summary 시트(키워드별 요약)**

| 열 | 뜻 |
|---|---|
| 유료 추정 앱 수 | 상위 10개 중 가격이 0보다 크거나 설명문에 유료 단어가 있는 앱 수 |
| 최근 6개월 업데이트 앱 수 | 최근 업데이트일이 6개월 안인 앱 수 |
| 리뷰 1,000개 미만 앱 수 | 평점 수가 1,000개보다 적은 앱 수 |
| **돈 내는 경쟁자 있음** (자동) | 유료 추정 앱이 1개 이상이면 "예" |
| **살아 있는 경쟁자 수** (자동) | 최근 6개월 안에 업데이트한 앱 수 |
| 리뷰 불만 반복 / Reddit 불만 (직접 입력) | 빈칸으로 만들어 둡니다. 직접 조사한 내용을 적으세요 |

**다시 실행해도 메모는 남습니다.** 덮어쓰기 전에 지난 결과의 직접 입력 열을 키워드별로 새 결과에 옮겨 담고, 지난 파일은 `money_check.bak.xlsx`로 복사해 둡니다. 이번에 pass를 뺀 키워드의 메모는 백업 파일에만 남습니다(백업은 실행할 때마다 직전 결과로 바뀝니다).

**apps 시트(앱 상세)**: 키워드 · 순위 · 앱 이름 · 판매자 · 가격 · 평점 수 · 평균 평점 · 출시일 · 최근 업데이트일 · 유료 단어 포함 · 찾은 유료 단어 · 유료 추정.

### 설정 (`config.toml`)

- `[money_check]`: 입력·출력 파일, pass 열 이름, "최근"의 기준 개월 수(`recent_update_months`), "돈 내는 경쟁자 있음"의 기준 앱 수(`paid_competitor_min`)
- `[paid_words] words`: 유료 단어 목록. 단어 단위로 찾고 대소문자를 무시합니다("pro"는 "product"와 맞지 않음).
- 요청 간격(1초)·재시도(3회)·국가(us)·상위 앱 수(10)·리뷰 기준(1,000)은 키워드 스캐너 설정을 같이 씁니다.

### 한계

- **"유료 추정"은 추정입니다.** 설명문에 "upgrade"·"unlock"이 다른 뜻으로 쓰여도 유료로 셉니다. 정확히 보려면 "찾은 유료 단어" 열을 눈으로 확인하세요.
