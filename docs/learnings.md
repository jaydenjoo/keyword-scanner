# learnings — 키워드 스캐너

형식: 증상 → 원인 → 해결 → 규칙

## L-001 긴 실행이 터미널 종료로 사라짐 (2026-10-02)

- 증상: 전체 스캔(207개)이 31개에서 멈추고 결과 엑셀이 없음.
- 원인: Claude Code 백그라운드 명령은 터미널이 닫히면 강제 종료됨. 당시 결과 저장은 Ctrl+C 때만 했음.
- 해결: 키워드마다 진행 기록 파일에 한 줄씩 쓰고 다시 실행하면 이어서 하도록 함(PR #2).
- 규칙: 10분 넘게 도는 작업은 처음부터 "끊겨도 이어서" 설계. 진행 기록은 줄 단위 flush, 마지막 줄은 잘릴 수 있다고 가정.

## L-002 경쟁 약한 상위 키워드 = 앱 이름 (2026-10-02)

- 증상: 경쟁 점수 최하위권이 "kabuddy: budget & kakeibo" 같은 특정 앱 이름으로 채워짐.
- 원인: 애플 자동완성은 일반 검색어뿐 아니라 앱 제목도 추천함. 앱 이름은 그 앱 하나만 걸려서 경쟁이 약해 보임.
- 해결: 상위 앱 제목과 똑같으면 "앱 이름 같음" 표시(PR #3). 실데이터 30개로 규칙을 먼저 확인한 뒤 구현.
- 규칙: 점수 상위 결과는 실데이터로 "정말 쓸 만한가"를 눈으로 확인하고, 판정 규칙은 실측 후 정한다.

## L-003 커밋 비밀키 검사 훅이 띄어쓰기 경로를 못 읽음 (2026-10-02)

- 증상: `git -C "/…/Keyword Scanner" commit`이 "git 저장소가 아니어서 비밀키 검사 불가"로 막힘. `cd … &&` 형식도 막힘.
- 원인: 훅이 `-C` 뒤 경로를 띄어쓰기에서 잘라 읽음.
- 해결: 세션 작업 폴더(프로젝트)에서 `cd`·`-C` 없이 `git commit` 실행.
- 규칙: 이 프로젝트에서는 커밋을 항상 세션 작업 폴더에서 경로 없이 실행. `rm -rf`도 막히므로 `rm -r <절대경로>`.

## L-004 사람이 손으로 고치는 파일을 프로그램이 덮어씀 (2026-10-03)

- 증상: 돈 검증 결과의 "직접 입력" 열(리뷰 불만·Reddit 불만)에 메모를 적은 뒤 다시 실행하면 메모가 사라짐(코드 리뷰 H1). 같은 이유로 키워드 스캐너를 다시 돌리면 `keywords_result.xlsx`의 pass 표시도 사라짐.
- 원인: 결과 파일을 늘 새로 만들어 바꿔치기함. 결과 파일이 사람이 고치는 입력 파일도 되는 순간 덮어쓰기가 곧 데이터 손실이 됨.
- 해결: 돈 검증은 덮어쓰기 전에 키워드별 메모를 읽어 새 결과에 옮겨 담고 `.bak.xlsx`로 백업. 키워드 스캐너는 매뉴얼 경고만(LATER.md).
- 규칙: "사람이 채우는 열"을 만드는 기능은 처음 설계할 때 "다시 실행하면 그 칸은?"을 같이 정한다.

## L-005 경쟁 점수가 낮다고 빈 시장이 아님 — 두 가지 함정 (2026-11-09)

- 증상: sourdough·metal detecting·hive inspection은 경쟁 점수 13~17로 "매우 약함"이었지만 상위 10개 중 7~8개가 2025~26년 새 앱이었음. 영국·캐나다·호주는 모든 분야 점수가 미국보다 낮게 나옴.
- 원인: ① 점수는 리뷰 수로 매기는데, AI로 갓 만든 앱들은 리뷰가 0~5개라 경쟁이 없는 것처럼 보임. ② 리뷰 수 절대값을 쓰므로 작은 스토어(영국·캐나다 미국의 약 12%, 호주 9%)는 같은 앱도 약해 보임.
- 해결: ① 출시일로 "최근 출시 앱 수"를 셈(PR #11). ② 나라 비교는 공통 키워드의 리뷰 최대값 비율로 보정(보고서에서 손으로, 결정 카드 #530).
- 규칙: 후보를 추천하기 전에 ① 최근 출시 앱 수 ② 1위 앱 설명문에 내 차별점이 이미 있는지 ③ 1~2점 리뷰 주제를 확인한다. 나라 비교는 보정 후에만 한다.

## L-006 긴 스캔이 응답 끊김으로 통째로 멈춤 — 두 번째 발생 (2026-11-09)

- 증상: 655개 스캔이 537번째에서 `http.client.IncompleteRead`로 종료(LATER 2026-10-03에 이미 적어 둔 문제가 실제로 발생).
- 원인: `IncompleteRead`·`BadStatusLine`은 `OSError`가 아니라 `HTTPException`이라 재시도 그물에 안 걸림.
- 해결: 당장은 "이어서 하기"로 재실행(실행마다 최대 3번 자동 재시도하는 감싸기 명령). 근본 수정은 PR #9.
- 규칙: 몇 시간짜리 실행 전에는 LATER의 "드물게 멈춤" 항목부터 확인한다 — 긴 실행에서는 "드물게"가 "반드시"가 된다.
