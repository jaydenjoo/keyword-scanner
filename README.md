# 미국 앱스토어 키워드 스캐너

씨앗 단어로 미국 앱스토어 자동완성 키워드를 모으고, 키워드마다 상위 10개 앱을 분석해 **경쟁이 약한 순**으로 엑셀에 정리합니다.
추가 설치 없이 Python 3.11 이상만 있으면 됩니다.

## 사용법

1. `seeds.txt`에 씨앗 단어를 한 줄에 하나씩 적습니다. `#`으로 시작하는 줄은 무시합니다.
2. 실행합니다: `python3 scan.py`
3. 결과는 `keywords_result.xlsx`에, 실패·건너뜀 기록은 `scan.log`에 남습니다.

다른 파일을 쓰려면 `python3 scan.py --seeds 내씨앗.txt --output 결과.xlsx --config 설정.toml`처럼 지정합니다.
중간에 Ctrl+C로 멈춰도 그때까지 분석한 키워드는 저장됩니다.

## 중간에 끊겼을 때 (이어서 하기)

- 키워드 1개 분석이 끝날 때마다 `keywords_result.progress.jsonl`(진행 기록)에 한 줄씩 남깁니다. 터미널이 닫히거나 Ctrl+C로 멈춰도 다시 `python3 scan.py`만 치면 **끊긴 키워드부터 이어서** 합니다.
- 끝까지 성공하면 진행 기록은 자동으로 지워집니다.
- 처음부터 다시 하려면 `python3 scan.py --fresh`.
- 씨앗 단어나 결과에 영향을 주는 설정(`[collect]`, `[criteria]`, `[score_weights]`, `[big_companies]`)을 바꾸면, 옛 기준과 섞이지 않게 알린 뒤 처음부터 합니다. 요청 간격 같은 `[request]` 값만 바꾸면 그대로 이어서 합니다. 프로그램 업데이트로 엑셀 열이 바뀐 경우에도 처음부터 합니다.
- 이어서 할 때는 자동완성을 다시 부르지 않고 처음 모은 키워드 목록을 그대로 씁니다. 처음 수집 때 자동완성 요청이 일부 실패했다면(`scan.log`에 기록) 그 목록도 일부가 빠진 채 쓰이므로, 빠짐없이 모으려면 `--fresh`로 다시 하세요. 인앱결제 확인 기록은 저장하지 않아서, 이미 확인했던 앱도 다시 확인합니다(그만큼 조금 느림).

## 걸리는 시간 (요청 사이 1초 대기)

씨앗 1개당 자동완성 26번을 거쳐 보통 키워드 200~260개가 모입니다.

| 인앱결제 확인                        | 키워드 1개    | 씨앗 1개 (약 250 키워드) |
| ------------------------------------ | ------------- | ------------------------ |
| 켬 (`check_in_app_purchases = true`) | 약 5초 (실측) | 약 20분                  |
| 끔 (`false`)                         | 약 1초        | 약 5분                   |

## 엑셀 열 설명

| 열                       | 뜻                                                                                                                                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 앱 이름 같음             | 키워드가 상위 앱 중 하나의 제목과 똑같으면 "예" — 일반 검색어가 아니라 그 앱의 이름일 가능성이 큼. 대소문자·대시·띄어쓰기 차이는 무시. 엑셀 필터에서 "아니오"만 고르면 숨겨짐. "budget daily"처럼 일반 단어와 같은 이름의 앱이 있어도 "예"로 나옴 |
| 경쟁 점수                | 0~100. 낮을수록 경쟁이 약함 (정렬 기준)                                                                                                                                                                                                           |
| 제목 포함 앱 수          | 앱 제목에 키워드 문구가 그대로 들어간 앱 수                                                                                                                                                                                                       |
| 리뷰 중간값·최대값       | 상위 앱들의 평점 수(userRatingCount) 기준                                                                                                                                                                                                         |
| 리뷰 N개 미만 앱 수      | N은 config의 `low_review_threshold`                                                                                                                                                                                                               |
| 대기업 여부·앱 수·판매자 | config의 `[big_companies]` 목록과 판매자·개발자 이름을 단어 단위로 대조                                                                                                                                                                           |
| 유료·인앱결제 앱 수      | 유료 앱 + (확인을 켰다면) 인앱결제가 있는 무료 앱                                                                                                                                                                                                 |
| 인앱 확인 실패 수        | 상세 페이지를 못 읽어 판단하지 못한 앱 수                                                                                                                                                                                                         |

## 설정 (`config.toml` 한 곳에서만)

- 요청 간격, 재시도 횟수(기본 3회 후 건너뜀), 리뷰 기준값, 대기업 목록, 점수 가중치를 모두 여기서 바꿉니다.
- 경쟁 점수는 항목별 비율에 가중치를 매겨 평균을 낸 값입니다. 리뷰 수는 로그 눈금이라 100→1,000과 10,000→100,000을 같은 차이로 봅니다.
- `monetized_apps`(유료·인앱 비율)는 경쟁 신호인지 수익성 신호인지 애매해서 기본 가중치를 0으로 두었습니다.

## 알아둘 점

- 애플 검색 API에는 인앱결제 정보가 없습니다. 그래서 앱 상세 페이지(apps.apple.com)의 "In-App Purchases" 항목을 읽어 판단합니다. 애플이 페이지 모양을 바꾸면 `인앱 확인 실패 수`가 늘어나고 로그에 기록됩니다.
- 자동완성 주소(search.itunes.apple.com)는 공개 문서가 없는 비공식 주소라 예고 없이 바뀔 수 있습니다.
